# Design

Use for Large/Complex features or when new architecture, data flow, or shared patterns are needed.

`design.md` sections:

- Overview.
- Existing patterns reused.
- Components/modules touched.
- Data flow.
- State and persistence.
- Error handling.
- Testing strategy.
- Risks and trade-offs.

Rules:

- Research codebase first.
- Prefer existing patterns.
- Include diagrams only when they clarify structure or flow.
- Link design decisions to requirement IDs.
