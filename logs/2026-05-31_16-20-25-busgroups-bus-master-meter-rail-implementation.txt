# BusGroups Bus Master Meter Rail Implementation

Date: 2026-05-31 16:20:25

## Summary

Implemented `src/features/busGroups/.specs/feature/bus-master-meter-rail`.

The BusGroups Bus Master now receives a transient live meter value for the selected BUS and renders it inside the existing central Bus Master fader rail. The existing rail width, height source, background color, fader thumb alignment, fader math, touch behavior, scroll lock, master mute/fader paths, MCA behavior, and BusMix meter streams were preserved.

## Runtime Changes

- Added `X32Protocol.getMeters2Path()` for `/meters/2`.
- Added `decodeMeter2BlobForBusMaster(blob, busId)` using the same X32 count-header and float decoding path as BusMix meters.
- Added `subscribeBusMasterMeter(busId, listener)` to `MixerControlProvider`.
- Added Bus Master meter simulation to mock and demo providers.
- Added `X32BusGroupsService.subscribeToBusMasterMeter`, which:
  - listens on `/meters/2`;
  - requests `/meters` with `['/meters/2']`;
  - renews every `8000ms`;
  - decodes `busId - 1`;
  - cleans up interval and OSC listener.
- Added transient `masterMeterDbfs` state to `useBusGroups`.
- Passed `masterMeterDbfs` only through `BusGroupsScreen -> MasterStrip -> GroupStrip -> VerticalGroupFader`.
- Rendered passive green/yellow/red continuous meter fill inside the existing master rail.
